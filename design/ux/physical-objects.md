# 实物交互合同

本文件把已授权要求变为制作输入。设计通过是明确动作和反馈，不能替代实机验收。

| 物件 | 完整链 | 必须检查的反例 |
|---|---|---|
| 档案 | 点书 → 打开 → 已遇见者肖像与来源 → 点页角翻 → 暂记推断 → ×或Esc合上 → 重开 | 字出纸外、未知身份泄漏、章签挡字、退出不保存、快速翻页后失控 |
| 箱子/信袋 | 锁扣 → 箱盖 → 信件暴露 → 拖取；信袋点真实信封再次检查 | 未打开即可取信、标签模拟取信、叉号融入背景、虚假装饰 |
| 信封 | 抬起 → 原桌面检查 → 同一对象拖动/翻面/缩放 → 放回 | 拆成地址/邮戳卡片、只换界面、错误操作吞输入、退回后角色脚位置丢失 |
| 地图 | 打开纸图 → 选已知地点 → 收图 → 一次行程 → 到达 | 多余步行确认、一次点击扣两次时间、转场中插入模态、到达仍锁控制 |
| NPC | 点人物 → 靠近 → 发言/可用话题 → 追问 → ×关闭 → 场景可继续 | 无可点区域、对话溢出、只能Esc退出、无线索的旁白、忘记已问话题 |

主管的一句自然对白和物件响应承担初次引导；不添加箭头、任务弹窗、常驻旁白或“查看详情/拿在手里”标签。声音、轻抬起、阴影、页动画和完成反馈需要按动作对齐。音频需要真实试听，不以 Dummy 驱动通过作证明。

UI 程序员负责纸内排版和输入生命周期；玩法程序员负责状态和存档；UX 检查不知道 Esc 的首次玩家；美术指导检查现有素材内的可读性；QA 负责反例；音效职责负责触发和试听。任何跨边界改动先跑 impact 列出受影响故事并回测。
