# 一百信 · Solmere Post

海边小镇，异常邮件部的一天。替五封来信核对地址、行程与旧事；查清事实之后，再决定哪些信息应该抵达。

Godot 4.7.2 / Windows x86-64。项目包含七处场景、四位居民、五封信的完整调查与结算，以及拆封、修复、证据推断、附件安排和存档恢复。内容目标是一次约 30–45 分钟的初次体验；这仍需真人试玩测量，自动演示与测试时长不能代替它。

## 开始游戏

Windows 成品目录中双击 `100letter.exe`。源码用户用 Godot 4.7.2 导入本目录的 `project.godot`，按 F6/F5 运行主场景。

从邮局门前到岗。用 WASD / 方向键或点击地面行走，点击门进入分拣桌；取第一封信，翻面，带着旧地名去小镇核对。画面中的当前目标会随正在处理的信和已有调查更新；靠近门牌、公告等物件后，在近景中实际查看文字与痕迹，才能记录发现。阅读不消耗游戏时间。移动、物件操作和已完成邮班的交接会推进一天；急件以实际交付时间判定。

| 操作 | 用法 |
|---|---|
| 行走 | WASD / 方向键，或点击路面；打开面板时暂停行走 |
| 调查、交谈 | 点击门牌、公告或人物；走近后观察物证或在场景中交谈 |
| 信袋、地图、档案 | 屏幕下方的物件图标；地图先查看路线与用时，再决定出发 |
| 信封 | 拖纸边移动，点右边缘翻面；字区滚轮阅读，纸边滚轮缩放 |
| 纸片拼合 | 拖放，右键旋转；按纸边、图纹和印记对齐 |
| 拆封与封回 | 按操作台上的轨迹与折线实际操作；粗糙操作留下痕迹 |
| 推断 | 把三份独立记录放到对应事实位置，再登记身份 |
| 照片 | 双击看背面，拖入信封或保留区；交付前仍可调整 |
| 声音设置 | 暂停菜单内分别调整音乐、音效、环境音，或开启主静音 |
| 暂停 / 全屏 | Esc / F11 |

普通错投会退回信件，不会让一天无法继续。严重损坏会进入中途失败画面，允许从该次拆封前的检查点恢复。先前调查仍保留。第四封的事实错误到晚间才复核；“送、暂扣、退回、留下照片”不被换算为善恶分数。

自动存档位于 Godot 的 `user://` 数据目录。保存使用临时文件和备份；损坏的主记录可回退到可验证备份。测试和演示各自使用独立存档。重新开始会询问是否替换当天记录。声音偏好另存于 `user://audio_settings.cfg`，不覆盖游戏进度；静音后仍保留各项音量。

## 五封信

| 信件 | 调查与操作 |
|---|---|
| 《旧名字的来信》 | 对照旧地名与眼前的地址记录 |
| 《赶在日落前》 | 核对收件人今日去向、交接方式和截止时间 |
| 《雨水里的邀请函》 | 拼合破损地址，调查迁居线索；可选拆封并修复，也可不拆完成 |
| 《迟到六年的情书》 | 联系独立物证，登记身份推断，亲手安排照片附件 |
| 《写给你的信》 | 在十一条纸质记录中核对编号和日期，完成归档 |

## 仓库结构

| 目录 | 内容 |
|---|---|
| `scenes/`, `scripts/` | 主场景、状态规则、交互与画面 |
| `data/game.json` | 信件、人物、地点、线索与结局内容 |
| `assets/locked_user/` | 包内和追加的原始美术，原文件保留 |
| `assets/display_user/` | 用户授权后，仅去外围白底的显示副本 |
| `assets/generated/` | 新生成的场景绘画与 Mira / June 图像 |
| `assets/characters/generated/` | 新绘画邮差的动作图集、Nora / 尘缘舞台立绘及图集清单 |
| `assets/fonts/` | OFL 中文字体与手写字体 |
| `assets/audio/` | 原创合成配乐、CC0 录音与拟音，以及来源和加工清单 |
| `specification/` | 用户提供的完整开发包，原样归档 |
| `docs/` | 设计对应、资产来源、变更与测试边界 |
| `tests/` | 真实 Godot 状态和交互回归 |
| `tools/` | 构建、音频制作、显示副本与演示工具 |

所有用户原图都有 SHA-256 清单。原图没有输入生成模型；显示副本保持尺寸及 RGB 像素不变，仅将授权范围内的外围近白色 alpha 设为透明。详见 [素材说明](docs/ASSET_PROVENANCE.md) 和 [显示副本清单](docs/DISPLAY_DERIVATIVES.json)。新增场景与人物的生成记录见 [新增绘画素材](docs/GENERATED_ASSETS.md)。

行走邮差使用独立生成的绘画动作图集，包含八张步行姿态、站立、递信和查看姿态；Nora 与尘缘的舞台形象也使用新绘画素材。工作证显示新邮差。原始角色设定另行保留，没有切肢、补手或输入生成模型。动作和生成方式的范围见 [角色记录](docs/CHARACTER_GENERATION.md)。

纸张、脚步、门、小铃、海浪、风、鸟鸣、街区与电车声音来自已核对许可的 CC0 录音或拟音；七处地点采用不同环境混音，并保留轻柔的原创合成配乐。作者、原始链接、许可及剪辑方法见 [声音来源](docs/AUDIO_PROVENANCE.md)。

## 验证与制作

```powershell
./tools/check.ps1 -GodotPath "C:/Tools/Godot.exe"
./tools/build.ps1 -GodotPath "C:/Tools/Godot.exe" -TemplatePath "C:/Tools/windows_release_x86_64.exe"
```

模板必须与引擎版本一致。Windows 构建输出到仓库旁的 `100letter-Windows`；源仓库不提交导入缓存、存档、可执行文件或视频。主线稳定版本保留在 `main`，后续协作应使用各自功能分支，通过正常合并保留对方历史。

100 种玩家画像用于模拟评审，另以 100 条确定性完整路线运行真实状态与存档测试。它们不是 100 名真人、满意度调查或 Steam 评分。参考依据、负面问题与修复见 [评审依据](docs/testing/PLAYER_REVIEW_BASIS.md)、[评审轮次](docs/testing/REVIEW_ROUNDS.md) 和 [验证记录](docs/testing/AUTOMATED_VALIDATION.json)。

棋摊对弈与塔楼屋的两个可选小游戏目前是明确标示的预留内容，不拦住五封信主流程。这是可游玩的五封信版本，并非完整商业发行；真人首轮体验时长、商店审核与全硬件兼容性尚未验证。

随 Windows 包提供的“全流程演示.mp4”是程序按真实界面操作录制的完整演示，使用独立存档，包含剧情与解法剧透。演示按 1 倍播放速度呈现，阅读与操作间停顿较紧，不代表首次游玩所需时间。
