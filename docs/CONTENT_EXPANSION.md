# 内容扩展与数据约定

本文件说明 `data/game.json` 如何从用户提供的 `specification/` 内容扩展为可交互叙事目录。原始规格文件不作修改。用户随后明确要求增强人物心理与书信质感，当前游戏正文已在原文基础上获得授权扩写；不能再称五封运行时正文与原规格逐字一致。

## 保留的内容

- 五封信保留《FIVE_LETTERS_PUZZLE_BIBLE.md》的原有核心句、称呼与署名，顺序不变，在句段之间加入日常细节与矛盾动机；原始全文仍在不可变的 `specification/` 中。
- 第一封的 Old Civic Hall 对应 Community Center；新邮戳与旧地名分开判断。
- 第二封不能拆，18:00 截止；亲自送达与尘缘代送分别产生到场观察与回执反馈。
- 第三封拼合得到 Rose Court 302 后仍要查迁出。Nora Vale 取代数据包中的 `nora_vale_placeholder`，不是新增替代角色。
- 第四封客观身份为 Mira → June，需三项独立物证；投递、暂扣、退还寄件人、拆后移除照片的后果不作善恶评分。
- 第五封保留十一条记录、三个处理词、原手写英文、主角短笺及 File / Keep / Destroy 的开放结局。前任身份不揭晓。

## 扩展范围

目录含 5 封信、30 条线索、7 个地点、27 个环境热点、4 位主要人物、20 条可重复阅读的对话、11 条旧档案记录。

新增文本包括信封观察、地点生活细节、旧记录的具体形态、问答、分支回执与晚间场景。新增内容围绕已有物证进行核对，避免以姓名猜谜、占卜或凭空口述代替独立证据。棋摊和塔罗店提供可选观察；没有核心答案被锁在这些旁支里。

### 后续授权的书信深化

用户要求的心理深度用于人物怎样解释自己的行为、怎样同时怀有不一致的愿望，而不是让每位镇民都说哲学格言。这里只借鉴自我辩解、动机冲突和言行不一致的心理结构，没有引用、改写任何受版权保护的译文，也没有让人物模仿某一部小说的固定话语。

| 信件 | 正文汉字数 | 本次声音与细节 |
|---|---:|---|
| 旧名字的来信 | 153 | Linnea 惦记靠窗的椅子、甜饼与谁多吃一块；保持轻快的日常招呼。 |
| 赶在日落前 | 137 | L. 反复换放车票，嘴上给人留退路，心里又盼着对方真会等。 |
| 雨水里的邀请函 | 172 | E. 从茶包盒里的扳手、旧椅子与轮值说起；搬家后的归属感留在一项普通邀请中。 |
| 迟到六年的情书 | 300 | Mira 对收杯子、挪纸袋的回忆暴露了等待；她想写得公平，又想让 June 先道歉。 |
| 写给你的信 | 298 | 前任从空着期限的暂扣条、排齐退信与“还在核实”谈起；保护别人和躲避追问混在一起，不替玩家下判决。 |

汉字数不含拉丁字母、标点和换行。原有地点、日期、人物、编号、客观解法与道德分支不变。二十条 NPC 回答均收为一至三句：尘缘说话实在并承认见闻有限；Mira 留有停顿和防备；June 更克制；Nora 以轮值、工具和搬家的琐事说话。对话所授予的线索和前置条件没有更改。

第一、二封不再把整封正文重复塞入结果段落。结果只留收件人的简短后续反应；正文由成功送达后的阅读入口单独呈现，既避免日终摘要重复，也不把不能拆的信提前给玩家看。

当前故事日设为 2026 年 7 月 24 日（星期五），与 Nora 邀请函中的周五活动一致；旧信仍为六年前的 2020 年 7 月 18 日。此为补齐规格未定年份的实现选择，不使用运行电脑的日期推动剧情。Case 04 的完整编号为 `S-0720-0718-04`，与旧清单唯一一条记录准确对应。清单另设同尾号、同月日但不同年份等近似项，要求比较完整记录，避免只点唯一醒目的答案。

原规格允许 6–8 片修复标签；本实现采用六片，与实际拖动、旋转和拼合交互一致。旧规格正文原样留存。

30–45 分钟是原规格的试玩目标。新增阅读与交叉调查内容服务于这一目标；本文不把文本量、自动化流程耗时或开发者熟练路线当作实测玩家时长。

## JSON 结构

`letters`、`locations`、`npcs`、`archive_records` 为数组。`clues` 为以 ID 为键的字典。所有显示文字由运行时排版，未烘焙进图片。

| 字段 | 约定 |
|---|---|
| `letters[].deadline` | 游戏内分钟；`1080` 为 18:00，`-1` 表示无明确截止。 |
| `letters[].body` | 当前游戏正文，含本轮用户授权扩写；存于数据不意味着允许在初始界面展示。 |
| `letters[].delivery_body_access` | 仅第一、二封有此可选元数据；`when` 规定成功投递后的展示时机，`label` 是收件人分享正文的入口名称。 |
| `letters[].recipient/sender/location` | 实际答案，用于状态验证；不能未经调查直接抄进人员档案。 |
| `letters[].outcome` | 按处理动作保存的回执或结局文本；第四封在晚间场景呈现。 |
| `locations[].travel` | 原始地点成本；地图移动的具体差值由时间系统计算。 |
| `locations[].asset` | `assets/locked_user/` 下的原始文件名；不对原文件重写。 |
| `locations[].position` | 地图归一化坐标。 |
| `hotspots[].position` | 地点画面归一化坐标。 |
| `hotspots[].clues` | 实际观察后才记录的证据 ID。 |
| `profile[].requires` | 所有前置线索收齐后才显示该字段；否则显示未知。 |
| `dialogues[].requires` | 所有前置线索收齐后才开放该问题。每位 NPC 在一个地点最多四问。 |
| `dialogues[].location` | 该问题适用的地点；重复语义仍使用独立问题 ID。 |
| `portrait` | 尘缘使用锁定原图；Mira、June 使用独立新增人物图；Nora 不挪用锁定人物头像。 |
| `archive_target` | Case 04 完整编号；不得以数组下标代替编号比对。 |

Mira 与 June 的新头像文件名为 `npc_mira.png`、`npc_june.png`，位于 `assets/generated/`。新增对白均为本次写作；没有从参考游戏复制文本。第三方素材的授权记录由工程素材清单另行管理。

## 证据与隐私边界

以下线索不在公共环境热点或普通问答中发放：

| 线索 ID | 唯一获取动作 |
|---|---|
| `repair_address` | 手动完成残损标签拼合。 |
| `case03_body` | 第三封信经实际工具拆封并展开内页。 |
| `old_photo` | 第四封信经实际工具拆封，取出夹层附件。 |
| `early_bench` | 第二封信走亲自投递路径时在场观察；代送不补发。 |
| `old_mail_log` | 合法开启第五封信并查看内页。 |
| `case04_number_match` | 玩家把旧清单与 Case 04 完整编号、日期进行对应。 |

这些动作由状态与交互系统控制。目录仅提供文字，不通过读取目录就自动解锁线索。

第一封的 `delivery_body_access.when` 为 `delivered`：成功投递后，由茶会朋友公开传阅便笺。第二封为 `evening_delivered`：亲自投递或代送成功之后，等到晚间由 Mira 同意附在回执里；逾期送达仍属于已投递。延迟或退回不能获得正文。元数据本身不会执行解锁，主界面必须结合实际处理状态和晚间状态判断；两封始终没有偷拆入口。

人员档案中的历史住址、行程、关系与笔迹均有证据前置。对话中的人物不把未见过的附件当作已知事实。

## 案件可解性

### Case 01

社区中心旧石牌提供 `old_civic_hall_name`；翻修告示提供 `community_center_history`。棋摊旧称呼为补充观察，不能代替两项核心地点证据。

### Case 02

尘缘问话提供 `chenyuan_sighting`；站台时刻表提供 `bus_to_lookout`。代送谈话解锁 `delegate_terms`，正式交接仍须由玩家操作。尘缘区分自己的见闻与不确定性，没有无动机撒谎。

### Case 03

先完成 `repair_address`，再从 302 得到 `resident_moved`。不拆路线可继续查看社区 `nora_registry`（明确含本人公开的观景台联系点）或公交站 `lookout_schedule`，均能核对去向。拆信路线通过 `case03_body` 获得强线索，然后按物理交互流程修复。私住新地址没有被公开补写。Nora 与 Mira 的相同姓氏不被当作代收依据。

### Case 04

不拆路线的三项独立物证是：居民楼 `old_nameplate`、社区中心 `event_archive`、独立署名卡 `handwriting_sample`。它们分别证实收件姓名、同日关系背景与寄件笔迹。拆后 `old_photo` 可参与三项物证组合。`early_bench` 只作寻找活动档案的提前提示；`mira_deflection` 是可被物证拆穿的回避，不作第三项物证。`current_relationship` 说明现在的相处状态，不泄露所有未来结果。

### Case 05

档案处理词可事先在邮局查看；十一条具体记录只在合法开启后呈现。`old_mail_log` 与 `case04_number_match` 分别表示看过清单和完成实物匹配。File / Keep / Destroy 在其他案件进入处理状态后开放，不宣布前任或玩家哪一方道德正确。
