## 从完整路线提取的结构

以下是简短分析，不转载攻略或解答表。引用作品机制与本项目设计推导分开记录。

**Faefever：人物与地点互相提供调查入口。** 从城镇交谈进入住宅调查，再由室内实物和文件推进后续路径；可选办法不能造成死路。Somni 页面保留了玩家遇到的分支阻断反馈。因此不能把“有多个选项”当作已实现可靠分支。我们的应用：已展示的文书直接可读；事实必须来自正确地点、时间和正反面；保留不同合法投递路径。[Wibir 完整路线](https://steamcommunity.com/sharedfiles/filedetails/?id=2628818474)、[Somni 路线及反馈](https://steamcommunity.com/sharedfiles/filedetails/?id=2421379653)。

**Loco Motive：早期物件要在后续仍有意义。** 整个故事跨角色与阶段收束，纸面信息、谈话和实物用途相互验证。我们的应用：同一封信、登记和收件人回应共同构成闭环，而不是每个画面都新增一套不相关菜单。借鉴其结构，不移植谜题答案、代码或图像。[完整文字路线](https://www.walkthroughking.com/text/locomotive.aspx)。

**Obra Dinn：记录帮助重新观察，完成必须有可感知的阶段收束。** 发现、记录、推断、结尾文书彼此关联。我们的应用：册中保存已观察事实，不自动输出作者答案；送达之后需要实际处理单，并让人物回应解释尚未完成的工作。[完整文字路线](https://www.walkthroughking.com/text/returnoftheobradinn.aspx)。

**Crushed in Time：物件动作产生后续条件。** 第一章反复利用环境中的同一物件改变情境。我们的应用是维护锁扣、箱盖、信件、翻面、工具的真实状态，拒绝用文字按钮替代物理动作。仅依据第一章，不能外推全部章节。[第一章](https://intoindiegames.com/walkthroughs/crushed-in-time-walkthrough-chapter-1-the-weight-of-words/)、[章节目录](https://intoindiegames.com/walkthrough-hub/crushed-in-time-walkthrough-hub/)。

**Pelican Post：邮递活动是认识居民、建立社区联系的契机。** 官方角色是来到 Port Pleasant 的 Pepper。当前公开材料强调送件、交谈、帮忙。对白截图中场景与双方人物仍然可见。应用到 Dear Somewhere：信件交付后的回应要包含具体的人与事，推动后续行动；保留用户提供的对白纸页 UI，不据此改成动物主角、像素画或驾驶玩法。官方及玩家提到驾驶背景滚动引起晕动，因此不会以快速滚屏制造“游戏感”。这仍是**公开材料研究，非 Demo 通关结论**。[Steam](https://store.steampowered.com/app/4458440/Pelican_Post/)、[开发者页面及反馈](https://drewg8.itch.io/pelican-post)、[开发日志](https://drewg8.itch.io/pelican-post/devlog/1529386/big-updates-steam-and-wholesome-direct-2026)。

**物件的生活感：** Tim Dawson 用熟悉的日常物品和细小行为传达生活变化。应用到本项目应是纸张、翻动、收件人的个人反应，而不是装饰堆积。[作者文章](https://blog.playstation.com/?p=364454)。

**依赖关系：** Ron Gilbert 区分谜题依赖与单纯操作流程。每个目标要有前置证据和收束，平行线不能变成不知道先做什么的一堆门。[开发者文章](https://grumpygamer.com/puzzle_dependency_charts/)。

Pelican Post 的官方物品栏原图也已在后台浏览器实际查看：当前物件完整显示 To/From、物品描述，旁侧保留下一物件，右上有明确的计数和关闭叉。我们的应用是保留物品的收寄语境、只呈现实际持有物及明确关闭路径；用户先前禁止的卡片拆信和“Take Out”文字代理动作不会因此重新引入。这是截图观察，不是操作验证。[官方物品栏图](https://img.itch.zone/aW1nLzI0MTY0Mzc0LnBuZw==/original/Ggk%2BUx.png)。

## 本轮落地的完整状态链

世界中的资料 → 点击接近/查看 → 实际展示完整纸面 → 记录当前可见来源 → × / Esc 放回 → 册中及存档保留事实 → 核对收件人 → 实际交付 → 收件人自然提到柜台处理单 → 返回邮局 → 手填、复核、落章 → 后续邮件可取。

1. 公开公告、住户页、时刻表、手册及旧账簿不再先显示一张几乎空白的“现场留存”假封面。
2. 移除可见文字上的隐藏逐行点击要求；一个已展开的纸面不再是打勾清单。
3. 照片正面保留真实图片，必须翻到背面才得到题注来源；不需要再点击每一行题注。
4. 旧门牌仍需移开遮挡才能看到，敲门仍需等回应。读取不能越过地点、时间、可用性和结束状态。
5. 第一封的两份文书改用容器排版，纸内留白、字号和换行统一；中英和三种窗口尺寸实际检查。
6. Elsie 的交付回应接住返回柜台的步骤，避免只把下一步写入不显示的内部状态。

这不是把旧五案替换为新三信或五日二十四封剧情。新长信、分散字句编辑、真实火漆材料步骤及更强人物关系仍是交付缺口，不能用旧五案路线通过来顶替。

## 设置必须抵达真实结果

| 控件 | 应影响的真实对象 | 验证方式 |
|---|---|---|
| 整体音量 | AudioServer Master 增益与静音 | 真实滑轨拖动至 0、再调高；检查实际混音总线 |
| 音乐音量 | 设置曲和场景音乐共同使用 SolmereMusic | 零值静音、恢复增益；音效保持可用 |
| 音效音量 | Foley 及环境声总线 | 零值静音、恢复增益；音乐保持可用 |
| 操作灵敏度 | 实际信件滚轮缩放与纸面平移 | 真实信件套件检查 0.5 / 2.0 的缩放步长，物品拖动仍贴合指针 |
| 文字速度 | 真正的 NPC 对白逐字显示 | 同一主管对白、相同约 0.22 秒观察慢/快显示字数；点击先补全，再推进 |
| 语言 | 设置/封面等界面与新文书排版 | 真实下拉选择、更换字体及排版；补齐新班次确认窗口的界面翻译。**不是全部剧情已经翻译** |
| 显示模式/分辨率 | 实际 Window、边框和渲染纹理 | 原生窗口几何套件检查真实值；不以保存的枚举值代替验证。全屏仍需单列原生验收 |
| 设置保存 | 独立偏好文件及新实例中的实际效果 | 关闭设置、重新构造 Host，检查恢复后的音频总线、语言和数值 |

这些检查不等于人的试听、操作舒适度或新手体验通过。具体结果、失败记录及剩余问题见 [阶段 QA](testing/CORE_LOOP_FULLFLOW_20261018.md)。

## 后续验收顺序

先完成当前状态链的实际窗口、试听、新手和错误路线验收，再按已有顺序推进背包、地图、NPC、行走及新三信。后续每条交付都要明确：玩家此刻为什么行动、可见线索在哪里、操作如何反馈、误操作如何恢复、做完如何自然知道下一步。已知完整路线的自动测试不能回答新手是否理解这些问题。
