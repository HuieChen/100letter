## 整班三次实际开封

用户确认计数范围为整个班次。每次封线产生本轮首个真实破口，消耗一次；同一封信修复封回后再次拆开，另计一次。Case05 内部工作封也消耗次数，但其阅读保持合法，不产生私人信的隐私违规。第三次可以完成，第四次在拿取开封工具前被核心阻止。看正反面、拖动物件、选择工具、尚未接触纸面的取消、只损伤纸面但未破封，都不计为一次开封；损伤本身仍保留。

模型 `opened_count` 与全班 `opening_history`（连续 serial、case_id、单封 ordinal、minute）互相校验。工作台在首破口时立即提交计数，未抽出或未读完也不能通过退出、保存或重启退款。已破开的第三封仍可继续抽出、展开、装回与封合。剩余邮件可用外部线索和合法未决处置完成流程。

## 真实封回与被察觉后果

私人信打开后，交付前必须真实折回内页、装入信封、合封舌并封合。封回不清除开封历史或已有纸面拆痕。收件时达到当前拆痕识别阈值，会各自降低工作声望与该人物信任；重复看同一记录、再点已交付邮件不会重复处罚。

累计三封不同私人信被收件人发现拆痕，触发 `repeated_detected_tampering`，声望进入最低档。仅开封三次、未被发现的行为、诚实待核实或迟到未送说明，不自动触发此失败。

直接交付的恢复点位于第三次交付之前。委托由尘缘送件时，察觉发生在约定到达事件，不能在交给尘缘时提前播放收件人反应；失败恢复至真实交给尘缘前，届时邮件仍在玩家手里。该分支明确撤回委托之后到回执之前的行动，避免恢复后卡在他人保管中。

最后一件采用委托时，尚未到达的回执也不能通过提前收工跳过。可在邮局明确等待预览过的剩余分钟再交班；等待至约定时刻只结算一次，普通阅读仍不推进时钟。
