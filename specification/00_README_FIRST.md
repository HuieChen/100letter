# Solmere Post — MVP 从零到一 Codex 文件包

这是一个给 Codex / AI 开发代理直接执行的完整 MVP 规格包。目标不是“按钮演示”，而是一个**短体量但完成度接近可公开试玩的独立游戏切片**。

## 使用方式
1. 将整个文件夹交给 Codex。
2. 首先复制 `02_PROMPTS/MASTER_CODEX_PROMPT.txt` 作为最高优先级开发指令。
3. 要求 Codex 在开始编码前阅读本包全部 `.md/.json` 文件。
4. `00_USER_ASSETS_LOCKED/` 内为用户原始素材，**禁止编辑、重绘、融图、风格化、AI 重生成、裁切重构、换色、改线稿、补全**。只允许在引擎中原样加载、等比缩放、平移、显示/隐藏。
5. `01_REFERENCE_IMAGES/` 是画风参考，不是待修改素材。
6. 缺失素材按 `02_PROMPTS/AI_ASSET_GENERATION_PROMPTS.md` 生成。新素材不得把 `00_USER_ASSETS_LOCKED/` 中任何角色/建筑“融”进生成图。
7. 若代码仓库已经有 Godot 项目，必须在原项目上增量开发；若无项目，默认使用 Godot 4.x。

## 目标试玩长度
约 30–45 分钟，一天工作循环，5 封信，4–7 个可访问地点，2–4 个主要 NPC。

## 核心验证
- 玩家是否享受“通过信件、人物、场景交叉推理收件人/地点”。
- 玩家在知道客观答案后，是否会对“送 / 延迟 / 扣留 / 退回 / 交由 NPC”产生真正犹豫。
- 拆信与修复是否是实际可操作的 gameplay，而不是按钮。

## 绝对禁止
- 不要做成视觉小说式“点下一句”Demo。
- 不要把所有谜题变成 Rebus 或密码锁。
- 不要把 UI 做成繁杂写实桌面或 3D 仿真。
- 不要篡改用户现有美术素材。
- 不要用生成式 AI 把用户角色或建筑重新画一遍。
